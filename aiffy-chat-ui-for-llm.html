Aiffy: An Adaptive UI for Large Language Models

Aiffy is a chat-first UI shell for local LLMs — a SvelteKit frontend on top of a FastAPI and Transformers backend, designed for fast prompt iteration, agent tooling, and everyday work with language models.

  • Aitetic
  • May 7, 2026

Aiffy is a chat UI for LLM workflows, built on a modern Svelte-based frontend and a Python model-serving backend. It is designed for developers and AI practitioners who need a clean, chat-first interface for large language models without taking on a hosted dependency.

The main goals of Aiffy are:

  • Provide a focused chat UI for LLM interaction.
  • Offer theme controls and accessible appearance options.
  • Integrate directly with local model servers and tooling.
  • Make prompt testing and conversation workflows fast and intuitive.

Why a Dedicated Chat UI for LLM Matters

A chat UI for LLM is more than a text box. Local and self-hosted large language models are powerful, but their default interfaces are usually a terminal, a raw HTTP endpoint, or a generic playground. None of these match how users actually want to talk to a model — turn by turn, with persistent history, configurable settings, and a layout that scales from a one-line prompt to a long technical conversation.

Aiffy combines the responsiveness of a browser-based interface with the flexibility to run custom models and tools locally. Unlike generic frontend demos, it is built specifically for chat-style LLM workflows: chat history, message rendering, settings panels, and a design that scales from quick prototype queries to longer, multi-turn conversations.

Key Characteristics of the Aiffy Chat UI

Chat-first: Aiffy is built around the chat interaction model. Conversations, message editing, regeneration, and streaming output are first-class concerns, not bolted-on features.

Local and self-hosted friendly: Aiffy runs against local model backends and prioritises privacy and offline capability, while also working as a deployed service on a shared host.

Theme-aware: it supports multiple UI themes — dark, light, system, and a KDE Breeze mode — so the chat UI fits into any working environment.

Tool-friendly: the shell is designed to work with model tooling such as prompt templates, intent classifiers, agent tools, and MCP servers.

How to Use the Aiffy Chat UI

To use Aiffy, run the project's Python server and open the web UI in your browser. The backend serves the local model and the frontend provides the chat interface, settings, and built-in option panels:

Example startup commands:

python server.py --model Qwen3-0.6B --prompt-style auto
python server.py --model ./models/gpt2 --prompt-style raw

The UI source lives in server/webui/, the built frontend lives in server/public/, and the model server entry point is server.py. A single Python process serves both the chat UI and the model — there is no separate Node runtime to manage in production.

What Sets the Aiffy Chat UI Apart

  • Flexible model selection: choose a local model by path, by name from the models/ folder, or by a Hugging Face Hub ID — the same launch command shape works for all three.
  • Adaptive prompt styles: the UI supports both auto chat templates for instruction-tuned models and raw concatenation for older base models like GPT-2.
  • Persistent UI preferences: theme and appearance settings are saved in the browser and restored on reload.
  • Fast rebuild workflow: frontend source changes in server/webui/src/ are compiled into server/public/ with npm run build.
  • Conversation history in the browser: chats are stored locally in IndexedDB, so the same Aiffy backend can serve many users without a shared database.

Chat Modes: Dialogue and QA

The Aiffy chat UI offers two conversation modes, switchable from the sidebar:

  • Dialogue (default) — sends the full active conversation on every turn, so the model sees its own prior replies and can refer back to earlier context.
  • QA — sends only the latest user message plus any system prompt, treating each turn as an independent question.

The selection is persisted in browser storage. Filtering happens on the way out, just before the request leaves the browser — the on-screen conversation is never modified, so switching from QA back to Dialogue mid-thread restores the full context for the next request.

Theme Support

The Aiffy chat UI supports four appearance modes through the Settings panel:

  • System — follows the operating system colour scheme automatically.
  • Light — forces the light palette regardless of OS preference.
  • Dark — forces the dark palette, suited to low-light work.
  • KDE Breeze — a Plasma-inspired theme with a blue accent on a dark base, with KDE-style radii and font tweaks.

The theme system is intentionally extensible: adding a new appearance is a matter of registering it in the theme enum, adding it to the settings list, and providing the matching CSS overrides.

Agent Tooling and Intent Classification

Beyond plain chat, Aiffy includes an agent tooling layer. The server can classify a user message into a tool call and execute it server-side, instead of returning a plain text reply. A tooling provider implements three methods — a classifier prompt, a result normaliser, and an executor — and the chat persona prompt and the classifier prompt are kept strictly separate, so tool support never leaks into ordinary chat replies.

A standalone test harness for the intent classifier ships with the project, so the routing of user phrasings to tool intents can be verified offline, without starting the HTTP server.

MCP Servers and Sampling Controls

Aiffy supports the Model Context Protocol. MCP servers can be configured directly from the settings UI as a JSON list and are invoked alongside built-in tools. Per-server usage statistics are tracked locally so it is easy to see which integrations are actually being used.

The Settings panel also exposes a full set of sampling parameters surfaced from the server's defaults: temperature, top_p, top_k, min_p, repeat_penalty, presence_penalty, frequency_penalty, dynamic temperature, XTC and DRY samplers, and a custom JSON field for arbitrary parameters. Empty values are shown as placeholders and are not sent on the wire — the server-side default is used instead.

Adaptive Deployment

Aiffy is built so the same chat UI for LLM works in two very different setups:

  • as a personal app on a developer workstation — for prompt iteration, model evaluation, and quick experiments;
  • as a deployed service on a shared host — for small teams who want a private LLM chat interface behind their own firewall.

That makes Aiffy a practical choice for experimentation, prompt tuning, and quick evaluation of local LLMs in a browser-friendly shell — and equally suitable as a long-running internal tool.

Under the Hood

When Aiffy starts, the server resolves the model in one of three ways: a direct path, a local repository folder under models/, or a Hugging Face Hub lookup. This makes it easy to switch between local and external model sources without changing the UI.

The server also determines the decoding mode from the temperature value rather than a separate sampling flag. In practice, values above ~0.0001 use stochastic sampling, while values close to zero use deterministic greedy decoding — one knob, one behaviour.

Who Aiffy Is For

The Aiffy chat UI for LLM is a strong fit when you want to:

  • experiment with local open-weight models in a polished chat interface;
  • iterate quickly on prompts and sampling parameters without leaving the browser;
  • build a small intent-classification and tool-execution layer on top of an existing model;
  • host a private LLM chat frontend on a developer workstation or an internal box;
  • prototype an AI-assisted internal tool before committing to a heavier stack.

Conclusion

Aiffy is a focused chat UI for LLM workflows. It pairs a SvelteKit chat interface with a FastAPI + Transformers backend, supports both base and instruction-tuned models, exposes a full set of sampling controls, and includes a clean tooling layer for intent classification and tool execution. With four built-in themes and explicit Dialogue and QA modes, it gives developers and small teams a private, browser-native chat experience over their own model — local on a workstation, or self-hosted behind a shared host.
